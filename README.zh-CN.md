# Story Engine / 剧情发动机

Story Engine 是一个面向长篇小说与连续剧情的开源结构诊断/共创框架。它关心的不是“设定听起来酷不酷”，而是一个阶段是否真的具备可持续推进结构：**启动、当前可结算目标、不行动代价、限制、有代价选择、行动反馈、收益与代价、永久状态残留，以及下一阶段牵引。**

> 当前公开版本：**0.1.1（英文核心文档维护版）**。本仓库不虚构外部用户数量，也不宣称无法复现的模型测试通过率。

## Story Engine 能解决什么问题

Story Engine 用来诊断长篇故事里的**结构性剧情问题**。

它尤其适合处理这些情况：

- 为什么这一卷像“重新开了一本书”？
- 为什么连续几个任务 / 副本越来越公式化？
- 为什么双线剧情看起来很多，但彼此没有影响？
- 为什么一个设定很有意思，却撑不起长篇？

## 快速示例

### 输入

**第一阶段**
- 主角救下了一名证人；
- 主角因此欠某个组织一个人情；
- 一个对手记住了主角。

**第二阶段**
- 主角因为一份新委托前往另一座城市；
- 证人、人情、对手追踪都没有影响新的调查。

### Story Engine 诊断

触发规则：
- `SE-RC-001`
- `SE-F-001`

发现：
- 第二阶段对第一阶段的继承很弱；
- 即使删除第一阶段，第二阶段大体上仍然成立；
- “证人 / 人情 / 对手追踪”本应成为向下承接的残留结果。

可行修复方向：
- 让新委托来自那名证人；
- 让进入新事件的资格取决于偿还组织人情；
- 让记住主角的对手在新城市持续施压。

**Story Engine 不只是判断一个剧情“有不有趣”，它更关心：上一个阶段是否真正生成了下一个阶段。**

## 为什么它不只是一个 Prompt

仓库包含：

- 8 个稳定规则 ID；
- 明确的输入字段与来源标记；
- 删除测试和反事实测试；
- 防止过度判断的风险边界；
- 可机读的模型行为评估集；
- 可实际运行的确定性仓库验证脚本；
- 通用结构化输出接口和 JSON Schema；
- 单阶段、跨阶段、双引擎示例。

## 八条规则

正向规则：`SE-RC-001` 通用循环、`SE-RC-002` 资源稀缺、`SE-RC-003` 反目标、`SE-RC-004` 现实/隐藏双引擎、`SE-RC-005` 规则压力。

风险规则：`SE-F-001` 循环重启、`SE-F-002` 公式化、`SE-F-003` 多发动机失衡。

风险规则只提示输入材料中的结构风险，不判整部作品失败。

## 使用

主入口是 `SKILL.md`。根据任务按需读取 `references/` 中的规则卡、输入规范、输出模板和诊断测试。

最小用法：

```text
请用 Story Engine 检查下面两个相邻阶段。
保留我已经确定的内容，不要替我补成正式设定。
重点判断第二阶段是否真正继承了第一阶段的后果。
```

## 测试

运行：

```bash
python tests/run_tests.py
```

该脚本只做确定性仓库验证，不伪装成 LLM 行为测试。

模型/Agent 行为评估请看 `tests/behavioral-eval.md` 与 `tests/test-prompts.json`。

## 项目范围

适合：剧情阶段推进、承接、资源发动机、反目标、现实/隐藏双线、规则压力、重复风险、多线失衡与终局收束。

不作为主工具处理：纯正文润色、完整人物弧光、百科式世界观、事实资料研究和文风模仿。
